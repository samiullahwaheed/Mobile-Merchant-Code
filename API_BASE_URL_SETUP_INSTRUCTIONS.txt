API Base URL Security Fix Instructions
======================================

Purpose
-------
This document explains the applied fix for hardcoded API endpoint exposure and how to run/build the app safely using --dart-define.


What was changed
----------------
1) Updated file:
   - lib/constant/app_api_end_point.dart

2) Change summary:
   - Removed hardcoded server URLs from source code.
   - Replaced debug/release URL switching logic with compile-time environment injection.
   - Added `String.fromEnvironment('API_BASE_URL', defaultValue: 'http://localhost:5004')`.

3) Current behavior:
   - The app now reads the API base URL from the `API_BASE_URL` dart-define.
   - If not provided, it falls back to: http://localhost:5004


How to run in different environments
------------------------------------
Development:
flutter run --dart-define=API_BASE_URL=https://mlitech.thepigeonhub.com

Staging:
flutter run --release --dart-define=API_BASE_URL=http://31.97.117.41:5004

Production build (APK):
flutter build apk --release --dart-define=API_BASE_URL=http://10.10.26.208:4004

Production build (App Bundle):
flutter build appbundle --release --dart-define=API_BASE_URL=https://mlitech.thepigeonhub.com


CI/CD recommendation
--------------------
1) Do NOT hardcode production URLs in Dart files.
2) Store environment-specific URLs in CI/CD environment variables.
3) Pass the value at build time using:
   --dart-define=API_BASE_URL=<value>
4) Use separate pipelines or variables for:
   - Development
   - Staging
   - Production


Files to modify in future (if needed)
-------------------------------------
1) Main endpoint configuration:
   - lib/constant/app_api_end_point.dart

2) CI/CD pipeline config:
   - Your pipeline file(s), for example:
     - GitHub Actions workflow
     - GitLab CI config
     - Bitbucket pipeline config
     - Any custom build scripts


Verification checklist
----------------------
[ ] App starts successfully with `--dart-define=API_BASE_URL=...`
[ ] Network requests go to expected environment URL
[ ] No production URL is hardcoded in Dart source
[ ] Staging and production builds use separate endpoint values
